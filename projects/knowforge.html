KnowForge

A private knowledge operating layer that compiles unstructured PDFs into a queryable wiki

Tech Stack: Python, FastAPI, PostgreSQL, Pinecone, LangGraph, BM25

Focus: Retrieval-augmented generation, knowledge compilation, entity graphs

Type: Personal R&D platform

Overview

Most RAG systems treat documents as a flat pile of chunks and hope the right one surfaces. KnowForge instead compiles a document corpus into an organised knowledge base: unstructured PDFs are parsed, synthesised at chunk level, and written out as a structured Markdown wiki that a human can read and a machine can query.

The result is a private, self-hosted operating layer for personal and organisational knowledge — no vendor, no data leaving the machine, and every answer traceable back to a source passage.

Compilation Pipeline

PDF ingest→Chunk synthesis→Entity extraction →Markdown wiki→Temporal facts
  • Chunk-level synthesis — each passage is rewritten into a standalone, self-contained note rather than stored raw, so retrieval does not depend on surrounding context.
  • Entity graphs — extracted people, systems, and concepts are linked across documents to support multi-hop questions.
  • Temporal fact tracking — facts carry validity windows, so the system can distinguish what was true at a point in time from what is true now.
  • Contradiction detection — conflicting claims between sources are surfaced explicitly instead of being silently averaged into one answer.

Hybrid Retrieval

Two retrievers, one ranking

Dense vector search (Pinecone) and lexical BM25 each fail in different ways — vectors miss exact identifiers, BM25 misses paraphrase. KnowForge runs both and fuses the ranked lists with Reciprocal Rank Fusion, which consistently beats either retriever alone without needing score calibration.

Agentic Query Workflow

A LangGraph workflow coordinates the request instead of a single retrieve-then-generate pass:

  • Query rewriting — ambiguous follow-ups are resolved into standalone questions.
  • Entity expansion — the graph contributes related entities the question did not name.
  • Candidate reranking — fused results are reordered against the rewritten query.
  • Verification — answers are checked against retrieved passages before being returned.

Why it matters

The hard part of retrieval is rarely the embedding call — it is deciding what a document means well enough to store it usefully. KnowForge is my working answer to that: treat knowledge compilation as a data problem first, and the retrieval quality follows.
